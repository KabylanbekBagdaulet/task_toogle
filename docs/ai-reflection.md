# AI reflection

I used an AI coding assistant to inspect the empty repository, propose a small task-tracker scope, draft the repository instructions, identify a focused Strategy-style filter decision, and suggest candidate risks. The context supplied to the assistant included the Assignment 05 requirements and the repository contents. I did not treat any generated claim as evidence until it could be tied to a file or a command result.

The most useful suggestion was to keep filter selection as a pure function. That made the behavior small enough to test directly and kept the visible screen focused on user actions. The strongest correction was to reject the assumption that the app saves tasks: the final interface says that data is cleared on refresh, and the risk register records that limitation instead of presenting it as a hidden defect.

One weak suggestion was the initial idea that a full persistence layer would improve the task tracker. That was not necessary for this assignment and would have expanded the scope, introduced credentials and access-control concerns, and made the evidence harder to verify. I did not implement it. I personally checked the repository structure, inspected every created source file, and ran the test, lint, and build checks. Those results support the readiness assessment, but they do not prove browser accessibility, visual correctness, or production behavior. The repository instructions improved the process by making safe commands, forbidden actions, and review gates explicit. The next improvement would be a small browser test suite and a continuous integration check, both reviewed separately.
